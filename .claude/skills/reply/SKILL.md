# /reply —— 一次处理一批评论

评论散落在页面上，处置集中在这里。**先代答清欠账，再分组给人看，逐条四选一，可中断。**

## 第零步：看同步提示（评论永远看得见，「动」之前先对齐）

`reply-queue.mjs` 的输出可能带同步提示。**评论已经直接从远端读出来给你了**（读永不挡）——但要处置（回帖/归档/改原型）前，若提示落后，先替用户把库对齐，顺序固定：

1. 本地有未保存改动 → 先存档：`git add -A && git commit -m "chore: 存档（合流前）"`（对用户说「先把你本地的改动存好档」；改动能归类时用更贴切的提交信息）
2. 合并远端：`git merge --no-edit origin/<默认分支>`（说「研发那边的最新内容已经合进来了」）
3. 然后照常处置。**禁 rebase、禁 stash**；merge 报冲突就停下来在会话里逐个处理，别硬来。

提示「连不上远端」时如实转告，先只读处理，别装作是全量。

## 第一步：清 @AI 欠账（代答）

运行 `node .baton/scripts/reply-queue.mjs --json`。对 `pendingAI` 组的每条：

1. 读该功能 `ledger/D*.yaml`，找能回答问题的条目
2. **找得到** → 两段式代答：
   - 先把完整推导写到 `answers/<线程id>.md`（引用台账原文 + 当时的讨论出处）
   - 再执行 `node .baton/scripts/thread-update.mjs answer <feature> <线程id> --body "<两三行结论>" --ledger D5 --derivation-file <featuresDir>/<feature>/answers/<线程id>.md`
   - 页面上只出现结论 + 「依据·台账 D5 ↗」+「查看推导 ↗」
3. **找不到** → 不硬答。`thread-update.mjs reply <feature> <线程id> --body "台账没有这条的记载，已转给持棒产品" --by AI`，该线程自然落入「需要你答」组

**铁律：只转述台账已有记载 + 必带出处；AI 不替产品做新决策。**（脚本层也挡：answer 不带 --ledger 会直接拒绝）

## 第二步：报清单，问策略

把分组结果讲给用户（🔴 阻塞实现排最前 → 🤖 刚代答完的 → 🟢 已代答待归档 → ✉️ 需要你答），然后用 AskUserQuestion 问一次策略：

- 「先处理阻塞项」（推荐，有阻塞时）
- 「已代答的批量归档，其他逐条来」
- 「全部逐条过」
- 「先放着，只看不动」

批量归档 = 对 answered 组逐条 `thread-update.mjs status <feature> <id> archived`。

## 第三步：逐条四选一

对每条待处置评论，展示原文 + 所在区块 + 已有代答，然后 AskUserQuestion：

1. **「你说观点，我来代拟回帖」**——用户口述 → 你拟**两三行提炼稿**给他过目（**不过目不发**；正文只放提炼，不贴长文）→ 过目通过后：用户原话 + 完整推导写 `answers/<线程id>.md`，再 `thread-update.mjs reply … --by <用户称呼> --ai-draft --derivation-file <该文件> [--ledger D<n>]`（页面显示「AI 代拟」标注 + 「原话与完整理由 ↗」）→ `status … resolved`
2. **「采纳，改原型」**——三合一：改 index.html 对应区块（沿用旧锚点 id）→ 若含新拍板则 `ledger-append.mjs` 入账 → 回帖说明采纳了什么 → `status … resolved`。原型改动先留在工作区，最后一步统一发新版
3. **「不改，说明理由」**——用户给理由 → 回帖 + 入台账（这是「为什么没选 X」的正式记录）→ `status … resolved`
4. **「跳过，下次再说」**——什么都不动，线程保持 open

**随时可中断**：用户说「先到这」就停，未处理的线程原样留在队列里，下次 /reply 接着来。

## 第四步：收尾

- 若第三步改过原型：提示「有 N 处采纳改动，现在发修订版给研发？」→ 用户同意就走 /handoff 流程（版本 +0.1，一批采纳 = 一版）
- 汇报：代答 N 条（都带了出处）/ 归档 N / 采纳 N / 不改 N / 剩 N 条下次

## 语言规范

对产品不说 git。回帖、状态变更由脚本即时同步给全团队（「研发那边马上能看到」），原型改动随下一版交接过去。
