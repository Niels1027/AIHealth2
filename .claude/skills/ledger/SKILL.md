# /ledger —— 决策台账

台账回答一个问题：**「这事当时怎么定的、为什么」**。它是 AI 代答的唯一弹药库——记得越勤，产品被打扰得越少。

## 查询（用户问「之前怎么定的」）

1. 读 `<featuresDir>/<feature>/ledger/D*.yaml`（按 id 排序）
2. 回答时**必带条目号**：「D5 定的：TTL 下沉到投递行……（拍板人 Niels，出处见 handoffs/H1.md）」
3. 用户要看全景 → 告诉他打开 `ledger/index.html`（可视化页，有原型锚点/讨论出处/被引用次数三处互链），或 `node .baton/scripts/open.mjs <feature>` 起页面后从原型链过去（装过全局命令可简写 `baton open`）

## 入账（对话里出现拍板）

用户说出决定性语句（「就用方案 B」「这个砍掉」「口径改成 X」）时：

1. `node .baton/scripts/ledger-append.mjs <feature> --title "<一句话结论式标题>" --conclusion "<拍板内容>" --decided-by <称呼> --source-kind session --source-ref "<出处描述>" --anchors <相关区块id>`
2. 回执一行：`已记录 D12「……」`——给用户当场纠错的机会
3. 纠错：「D12 记错了」→ `--amend D12`，不新开条目。**改结论时看一眼标题**——新结论若推翻了标题，同一次 amend 里连 `--title` 一起改（脚本回执会列出改了哪些字段，标题没跟上时也会提醒，但别依赖提醒兜底）

判断标准：**结论性、影响后续实现、换个人也需要知道**的才入账；过程性讨论不记。宁可少记准，不可多记杂。

## 三条边界

- 台账界面**只读**——所有写入走上面两条路径，绝不让用户（或你）手编 `D*.yaml` / `ledger/index.html`（后者是生成物，会被覆盖）
- 你只提炼用户说过的话，**不把自己的建议写成拍板**；拿不准是不是拍板就问一句
- 代答（/reply 里）引用台账时，被引用计数会自动出现在可视化页——不需要手工维护
