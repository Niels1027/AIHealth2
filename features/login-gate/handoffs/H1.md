## 这版是什么

第一版交接，没有上一版可比。

需要先知道的前提：**现网没有登录页**。今天的身份是 `src/components/shared.ts` 里一个 `hr_role` cookie，UI 就是 ChatApp 侧栏底部那对「用户 / 管理员」药丸——改 cookie 就能变管理员。这次是从零加一张入口页，并把那个开关拆掉。

原型里两段内容：上面是登录页正式帧，下面是「进入后 · 侧边栏底部身份区」的现状 / 新版对照。下面那段只是说明改动落点，不是要你新做一个组件。

## 原型里哪些是假的（演示替身）

这一节是防止照抄原型里临时实现的唯一屏障，逐条对照着做。

1. **【安全】管理口令写死在页面 JS（`moss-2026`），浏览器端比对** —— `b-admin-key`
   → 新增服务端校验接口（`src/app/api/auth/route.ts`，仿现有 10 个 route 的模式）；口令只存服务端 env（本项目现无任何 `NEXT_PUBLIC_` 变量，**不要为此破例**），只在服务端比对；前端只递交输入、收 cookie/session。

2. **【安全】进入后的身份只活在页面 JS 变量里，刷新即丢** —— `b-identity-card`
   → 体验用户与管理员都要有可持久化的会话；管理员那份必须服务端签发、前端不可伪造。现网 `hr_role` cookie 是纯前端字符串，照它的路子做等于没改。

3. 知识库状态行的「3 本书 · 1,284 段」是写死的示意数字 —— `b-kb-status`
   → 走现有 `/api/health`（`src/app/api/health/route.ts` 已返回 `stats.readyDocuments` / `chunks` / `embeddedChunks` 与 `embedding.ok`）；未就绪时按现网 ChatApp 的说法降级，别显示假数字。

## 已拍板的约束（改动前先看这两条）

- **D1** 登录方式 = 体验直入，不做注册与凭证。不要加手机号验证码、邮箱密码或注册流程；进入后身份是「体验用户」，本机会话，不收集个人信息。
- **D2** 管理员走同一入口，不开 `/admin/login`，登录页上也不放「以用户 / 以管理员身份」的选择。身份由入口决定，进入后不可切换。

## 开放问题（可自行判断）

- 登录态的具体载体（httpOnly cookie / JWT / server session）没定，选你顺手且满足「前端不可伪造」的即可。
- 体验用户会话的有效期没定。
- 未登录时是整站拦截还是只拦 `/admin`，看现有路由结构决定。
- 登录页的移动端断点没画，参照 ChatApp 现有的 `md:` 处理。
